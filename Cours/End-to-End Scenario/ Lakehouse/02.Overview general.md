
## Ingestion des données d'exemple 

1- Téléchargez le fichier _dimension_customer.csv_ à partir de ce lien https://shorturl.at/3LUNz

2.  Dans l’onglet Accueil, sous Obtenir des données dans votre lakehouse, nous avons les options permettant de charger des données dans le lakehouse.Sélectionnez Nouveau Dataflow Gen2

![image](https://github.com/user-attachments/assets/0c6cd4cf-6bb5-4411-ac11-0043a446ad9a)

3. Dans l’écran **New data flow** , sélectionnez Importer à partir d’un fichier Texte/CSV.

  
4. Dans l’écran Se connecter à la source de données, sélectionnez le bouton  Charger le fichier. Faites glisser et déposez le fichier dimension_customer.csv que vous avez téléchargé à l’étape 1. Une fois le fichier chargé, sélectionnez Suivant

![image](https://github.com/user-attachments/assets/9033baba-72c8-4919-8043-d917cdc955e4)


5.  Dans la page Aperçu des données du fichier, affichez un aperçu des données, puis sélectionnez Créer pour continuer et revenir au canevas du Data Flow. 

6.  Dans le volet Paramètres de la requête, mettez à jour le champ Nom avec dimension_customer

![image](https://github.com/user-attachments/assets/dee79c81-5e7e-41de-8aeb-ba9c7ca41914)


7. Dans ce tutoriel, vous avez associé les données client à un lakehouse. Si vous avez d’autres éléments de données que vous souhaitez associer au lakehouse, vous pouvez les ajouter :

    Dans les éléments de menu, sélectionnez Ajouter une destination de données, puis lakehouse. À partir de l’écran Se connecter à la destination des données, connectez-vous à votre compte si nécessaire et sélectionnez        Suivant.

    Accédez à la wwilakehouse de votre espace de travail.

Si la table dimension_customer n’existe pas, sélectionnez le paramètre Nouvelle table et entrez le nom de la table dimension_customer. Si la table existe déjà, sélectionnez le paramètre Table existante et choisissez dimension_customer dans la liste des tables de l’Explorateur d’objets. Cliquez sur Suivant

![image](https://github.com/user-attachments/assets/6bd76038-d822-4855-8f8c-2cfeb87ae48b)

Dans le volet Choisir les paramètres de destination , sélectionnez Remplacer comme méthode Mise à jour. Sélectionnez Enregistrer les paramètres pour revenir au canevas du Data Flow


8. Pour continuer, sélectionnez Publier en bas à droite de l’écran

![image](https://github.com/user-attachments/assets/362c4a61-2942-4631-8891-42d8fdff1a86)

9. Renommez le Dataflow en **Load Lakehouse Table** et sélectionnez **Enregistrer**.

10.  Sélectionnez l’option **Refresh now** pour actualiser le data flow Cette option exécute le flux de données et déplace les données du fichier source vers la table lakehouse. 
Pendant qu’il est en cours, vous voyez un cercle tournant sous colonne Actualisée dans l’affichage d’élément.

![image](https://github.com/user-attachments/assets/c97b13c7-7660-4cd7-a1c7-9e3804507ab3)

11.  Une fois le flux de données actualisé, sélectionnez votre lakehouse **wwilakehouse** table Delta dimension_customer

![image](https://github.com/user-attachments/assets/1357935f-91df-4664-9316-9119947effe7)


12.  Sélectionnez la table pour afficher un aperçu de ses données. 
Vous pouvez également utiliser le point de terminaison SQL du lakehouse pour interroger les données avec des instructions SQL. 
Sélectionnez point de terminaison SQL dans le menu déroulant Lakehouse en haut à droite de l’écran.

![image](https://github.com/user-attachments/assets/31a8188a-4dcc-4c00-a6d9-e5c78f3a99c5)


13. Sélectionnez la table dimension_customer pour afficher un aperçu de ses données ou sélectionnez Nouvelle requête SQL pour écrire vos instructions SQL.

![image](https://github.com/user-attachments/assets/9645216b-2aea-4849-aec1-79e0054aa830)


14. L’exemple de requête suivant agrège le nombre de lignes en fonction de la colonne BuyingGroup de la table dimension_customer. Les fichiers de requête SQL sont enregistrés automatiquement pour une utilisation ultérieure, et vous pouvez renommer ou supprimer ces fichiers en fonction de vos besoins.

Pour exécuter le script, sélectionnez l’icône Exécuter au dessus du fichier de script.

![image](https://github.com/user-attachments/assets/cc5482b7-851f-4dee-8ad3-14905a728fc4)





## Créer un rapport

1. Pour ajouter les données au modèle sémantique
 Ouvrez votre lakehouse et basculez vers la vue du Point de terminaison d’analytique SQL. Dans l'onglet Reporting, sélectionnez Gérer le modèle sémantique par défaut et sélectionnez les tables que vous souhaitez ajouter au modèle sémantique. Dans ce cas, sélectionnez la table dimension_customer.

![image](https://github.com/user-attachments/assets/8b1cfc1e-4733-40c9-a98a-c03bfe1a208c)


2. Une fois la table ajoutée, Fabric crée un modèle sémantique portant le même nom que le lakehouse.

![image](https://github.com/user-attachments/assets/17de6a92-8cfe-40fe-a7f0-f1fa801a7a8e)


3. Dans le volet de modèle sémantique, vous pouvez afficher toutes les tables. Vous disposez d’options pour créer des rapports à partir de zéro, des rapports paginés ou laisser Power BI créer automatiquement un rapport en fonction de vos données. Sélectionnez Créer automatiquement un rapport.

![image](https://github.com/user-attachments/assets/ebd000d4-6062-46a2-8deb-4d1f6478e709)


4. Étant donné que la table est une dimension et qu’il n’y a aucune mesure, Power BI crée une mesure pour le nombre de lignes et l’agrège sur différentes colonnes, et crée différents graphiques, comme illustré dans l’image suivante. Vous pouvez enregistrer ce rapport pour l’avenir en sélectionnant Enregistrer dans le ruban supérieur. Vous pouvez apporter d’autres modifications à ce rapport pour répondre à vos besoins en incluant ou en excluant d’autres tables ou colonnes.

![image](https://github.com/user-attachments/assets/5ed21ce2-87cb-4b50-9d43-b06bf889dc14)
